# 아카이브 홈 개선 설계

- 날짜: 2026-08-08
- 대상: `docs/` PWA의 아카이브 홈('우리 데이트 기록')
- 상태: 승인됨

## 문제

홈(`docs/app.js`의 `renderArchive`)이 코스를 날짜 내림차순 카드로 평면 나열한다. 카드에
담기는 정보는 `docs/courses/index.json`의 `date` / `title` / `meta` 세 개뿐이라 세 가지가
막혀 있다.

1. **밋밋하다.** 카드가 텍스트 세 줄이라 어떤 데이트였는지 한눈에 안 들어온다.
2. **찾기 어렵다.** 코스가 쌓이면 스크롤만 길어진다. 거를 수단이 없다.
3. **관리가 번거롭다.** 부엌 페이지 목록이 `app.js`의 `KITCHEN` 배열에 하드코딩돼 있어
   페이지가 늘 때마다 코드를 고쳐야 한다.

세 문제의 뿌리는 하나다 — `index.json`에 구조가 없어서 뱃지도 필터도 만들 수 없다.

증상으로 `meta` 문자열이 과부하 상태다. 날짜가 `title`과 `date`에 중복되고
(`"홍대 방탈출 데이트 · 2026-08-08(토)"`), 이모지가 `title`에 박혀 있고
(`"🌊 워터밤 서울 2026 데이트"`), 동탄 항목은 평점까지 문자열에 섞여 있다.

## 범위 밖 (명시적으로 안 함)

- **사진.** 리포가 PUBLIC이고, 리포를 private으로 바꿔도 Pages 사이트는 (Enterprise가
  아닌 이상) 공개 URL이다. `docs/`에 넣는 건 뭐든 인터넷에서 열린다. 인물 사진을 공개
  URL에 올리지 않기로 결정했다.
- **평점·후기 등 사후 기록.** 데이터 모델에 추가하지 않는다.
- 검색창, 지도 뷰, 다중 필터 조합.
- 코스 상세 페이지 레이아웃 변경.
- 스킬의 `render_course.py` 수정. 이 설계는 아카이브 목록 전용 메타만 다루므로
  코스 렌더러와 접점이 없다.

## 자동 파생값 검토 결과

카드 재료를 코스 JSON에서 자동으로 뽑으려 했으나 대부분 쓸 수 없다.

- **정거장 수** — 칭다오는 4일치 합계(29곳)라 과장이고, 신사는 코스 A(4곳)/B(8곳) 중
  하나만 실제로 간다. 두 경우 다 합계가 거짓이 된다.
- **`courses[]` 개수** — 배열이 두 가지 뜻으로 쓰인다. 신사는 **선택지 A/B**,
  칭다오는 **4일치 일정**. 같은 숫자가 다른 의미다.
- **`cost`** — 코스별로 따로 있어 대표값을 정할 수 없다.

살아남는 파생값은 `has_outfit` 하나다. 따라서 카드의 주력 정보인 `region`과 `tags`는
저장 시점의 수동 입력이다.

## 데이터 모델

`docs/courses/index.json`의 항목 스키마. 기존 5개 필드를 유지하고 4개를 추가한다.

```json
{
  "slug": "hongdae-escape-2026-08-08",
  "title": "홍대 방탈출 데이트",
  "meta": "오후 5시 · 약 5시간 · 방탈출 + 맛집 + LP바",
  "date": "2026-08-08",
  "added": "2026-08-06T21:05:40",

  "region": "홍대",
  "tags": ["액티비티", "실내", "맛집", "술"],
  "emoji": "🔓",
  "has_outfit": true
}
```

| 필드 | 타입 | 용도 |
|---|---|---|
| `region` | 문자열 1개 | 커버 그라디언트 색상, 필터 칩 |
| `tags` | 문자열 배열 | 필터 칩 |
| `emoji` | 문자열 | 커버 칸에 크게 표시 |
| `has_outfit` | 불리언 | 👔 뱃지. 코스 JSON에서 자동 파생 |

부엌 항목은 여기에 두 필드를 더 갖는다.

| 필드 | 값 | 용도 |
|---|---|---|
| `kind` | `"kitchen"` | 코스가 아님을 표시 |
| `href` | `"kitchen/mosu-steak-2026-08-02.html"` | 링크 대상 (`?c=<slug>` 대신) |

`kind`가 없으면 코스로 간주하고 `?c=<slug>`로 링크한다. 부엌 항목도 `slug`를 갖는다 —
링크에는 쓰이지 않지만 목록 안에서 항목을 식별하는 키이고, `save_course.py`의 중복
제거 로직이 `slug`를 전제로 한다.

### region이 1개 문자열인 이유

워터밤은 실제 동선이 "송파 점심 → 킨텍스 워터밤"이라 지역이 둘이다. 메인인 킨텍스를
쓴다. 지금 배열로 만들면 나머지 5개가 전부 원소 1개짜리 배열이 된다. 이런 케이스가
더 쌓이면 그때 배열로 바꾼다.

### 태그 어휘 (고정 목록)

축을 섞으면 필터 칩이 지저분해지므로 3개 축으로 나눈다.

| 축 | 태그 |
|---|---|
| 활동 | `맛집` `카페` `술` `영화` `액티비티` `페스티벌` `전시` `산책` |
| 환경 | `실내` `야외` |
| 규모 | `여행` (1박 이상. 없으면 당일) |

`save_course.py`에 상수 `TAGS`로 둔다. 목록에 없는 태그가 들어오면 **에러로 거부**하고
허용 목록을 출력한다. 새 태그가 필요하면 상수에 한 줄 추가한다.

## 저장 워크플로 (`save_course.py`)

```bash
python3 save_course.py course.json --slug hongdae-escape-2026-08-08 --date 2026-08-08 \
  --region 홍대 --tags 액티비티,실내,맛집,술 --emoji 🔓
```

- `--region` / `--tags` / `--emoji` 는 모두 **선택**. 주지 않으면 해당 필드를
  `index.json` 항목에서 생략한다.
- `--tags`는 쉼표 구분. `TAGS` 목록에 없는 값이 하나라도 있으면 에러로 종료하고
  허용 목록을 출력한다.
- `has_outfit`은 코스 JSON에서 자동 파생한다:
  `any(c.get("outfit") for c in data.get("courses", []))`
- 기존 동작은 그대로 유지한다 — 같은 `--slug`면 업서트, 날짜 내림차순 정렬,
  `docs/courses/<slug>.json` 기록.
- 부엌 항목은 이 스크립트가 다루지 않는다. `index.json`에 직접 넣는다.

## 홈 화면 (`docs/app.js` `renderArchive`, `docs/index.html` CSS)

### 카드 구조

가로 2단. 왼쪽은 폭 약 64px의 **커버 칸**, 오른쪽이 본문이다.

커버 칸은 지역별 그라디언트 배경에 `emoji`를 크게 가운데 놓는다. 사진 없이 카드마다
색이 달라지게 하는 것이 목적이다.

본문은 위에서부터 네 줄이다.

1. **날짜** — 작게, 강조색 (`.arch-card .date` 유지)
2. **제목** — 굵게. 날짜·이모지를 제거한 이름만
3. **meta** — 흐린 색 한 줄 (`.arch-card .m` 유지)
4. **뱃지 줄** — `region`은 채워진 알약, 각 `tag`는 테두리만 있는 알약,
   `has_outfit`이면 👔

### 폴백

`region` / `tags`가 없는 항목은 4번 줄을 통째로 생략한다. `emoji`가 없으면 제목 첫
글자를 넣고, `region`이 없으면 커버를 회색 그라디언트로 칠한다. 결과적으로 **지금
카드와 같은 모양**이 된다. 백필 안 된 항목이 섞여도 화면이 깨지지 않는다.

### 지역 → 색

지역 이름을 문자열 해시로 0~360 각도로 바꿔 **색상(hue)만** 정하고, 채도와 밝기는
고정한다. 팔레트를 손으로 관리하면 지역이 늘 때마다 코드를 고쳐야 하지만, 해시는 새
지역이 와도 자동으로 색이 정해지고 톤은 통일된다. 다크모드는 밝기 값만 다르게 쓴다.

### 그룹핑

연도 헤딩을 넣되 **목록에 연도가 2개 이상일 때만** 렌더한다. 지금은 전부 2026이라
화면에 나타나지 않고, 2027 항목이 생기면 자동으로 갈라진다. 5개짜리 목록에 헤딩
하나만 있는 것은 소음이다.

### 필터

목록 위에 칩 줄을 놓는다. `전체` 다음에 **실제로 존재하는** 지역들, 그다음 **실제로
존재하는** 태그들. 태그 어휘 전체를 칩으로 깔지 않는다 — 결과가 0건인 죽은 버튼이
생긴다.

한 번에 **하나만** 선택된다. 조합 필터는 빈 결과를 만들고, 그러면 그것을 설명하는
UI가 또 필요해진다.

선택 상태는 URL에 담는다. `?r=<지역>` 또는 `?t=<태그>`. 라우터가 이미 `?c=` / `?f=`를
쿼리로 처리하고 `popstate`를 듣고 있으므로 홈 라우트의 하위 상태로 붙는다. 칩 클릭 시
`history.pushState` 후 `main()`을 다시 돌린다. 뒤로가기가 동작하고 필터된 화면을 그대로
공유할 수 있다.

라우터 분기 순서는 기존을 유지한다 — `#해시` → `?c=` → `?f=` → 홈. `?r=` / `?t=`는
홈 분기 안에서만 읽는다.

### 부엌 통합

`app.js`의 `KITCHEN` 상수를 삭제하고 항목을 `index.json`으로 옮긴다. 부엌 항목은
코스와 **섞어서 날짜순 하나의 목록**으로 렌더하고, `emoji`(🍳)와 `region`(`집`) 뱃지로
구분한다. `집` 필터 칩으로 부엌만 따로 볼 수 있다.

링크는 `kind === "kitchen"`이면 `href`, 아니면 `?c=<slug>`.

`sw.js`의 `/kitchen/` navigate 예외는 **그대로 둔다**. 그것은 SW가 앱 셸을 돌려주는
별개 문제를 막는 장치이며 이 변경과 무관하다.

### 서비스워커

`app.js`와 `index.html`이 바뀌므로 `docs/sw.js`의 `CACHE` 버전을 올린다.

## 백필

기존 6개 항목에 채울 값이다. `title`에서 날짜와 이모지를 걷어내 각각 `date` / `emoji`
필드로 옮긴다.

| slug | title | emoji | region | tags |
|---|---|---|---|---|
| `qingdao-2026-08` | 칭다오 3박 4일 | 🍺 | 칭다오 | 여행, 맛집, 야외 |
| `hongdae-escape-2026-08-08` | 홍대 방탈출 데이트 | 🔓 | 홍대 | 액티비티, 실내, 맛집, 술 |
| `dongtan-2026-08-01` | 동탄역 영화 데이트 | 🎬 | 동탄 | 영화, 실내, 맛집 |
| `sinsa-2026-07-26` | 신사 · 가로수길 오후 데이트 | ☕ | 신사 | 카페, 산책 |
| `waterbomb-2026-07-25` | 워터밤 서울 2026 | 🌊 | 킨텍스 | 페스티벌, 야외 |
| (부엌) `mosu-steak-2026-08-02` | 집마카세 · 모수식 스테이크 | 🍳 | 집 | 맛집, 실내 |

`has_outfit`은 각 코스 JSON에서 확인해 채운다.

동탄 항목의 `meta`에 `⭐ 실제 평가 4.5/5`가 들어 있다. 사후 기록은 범위 밖이므로
**손대지 않고 문자열 그대로 둔다**.

## 검증

`python3 -m http.server`로 `docs/`를 띄우고 브라우저로 확인한다. 사용자가 화면을 볼 수
없는 상황이므로 결과는 글로 보고한다.

1. 필터 칩 클릭 → URL이 `?r=홍대`로 바뀌고 목록이 걸러진다. 뒤로가기가 동작한다.
2. `region` / `tags`가 없는 항목을 임시로 넣어도 카드가 깨지지 않는다 (폴백).
3. 다크모드에서 커버 그라디언트 위의 이모지가 읽힌다.
4. 부엌 카드 클릭 시 SW가 앱 셸을 돌려주지 않고 실제 HTML로 이동한다 (기존 회귀 지점).
5. `?c=` / `?f=` / `#<mode>:<payload>` 세 라우트가 그대로 동작한다.
6. 연도가 하나뿐일 때 연도 헤딩이 나타나지 않는다.
